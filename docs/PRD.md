## 1 项目背景

HKSC 起源于个人港股研究实践。个人投资者需要持续完成行情核对、机会筛选、候选跟踪、效果观察和周末复盘，但这些工作容易分散在数据工具、聊天记录、表格和临时脚本中。

MCP 和 Skills 改善了 AI 获取金融数据的能力，却没有自动解决候选如何延续、判断如何验证、失败如何记录的问题。原 HKSC 围绕这些需求形成了日常研究流程，使用恒生聚源数据地图 MCP、腾讯自选股 WeStock 与 Futu Skills 获取不同类型的研究输入。

公开版保留产品目标、研究方法和工程约束，去除私人实例与生产资产。已有抽取代码可以支撑部分流程，但不能作为完整产品范围的替代。

## 2 产品目标

在经过流动性与可交易性筛选的港股研究池中，发现 **5–60 个交易日的中期机会**，提供每日行动计划、策略效果观察和周末复盘。

| 目标 | 使用者应当得到的结果 |
| --- | --- |
| 发现中期机会 | 少量符合方法的候选、入选依据、风险条件，以及没有合格机会时的明确结论 |
| 每日行动计划 | 当天关注对象、等待条件、已记录候选的变化、需要人工复核的问题 |
| 策略效果观察 | 信号后续表现、失效情况，以及按明确口径计算的风险、成本与基准比较 |
| 周末复盘 | 本周机会和判断的汇总、市场环境、有效与失效条件、下周需要继续验证的问题 |

### 2.1 第一版完成标准

第一版需要用连续多个研究时点展示完整闭环，而不是只证明扫描器可以运行：

1. 使用标准输入发现候选，生成每日行动计划。
2. 下一轮接续原有候选，说明变化及处理依据。
3. 对已发生的研究事件生成明确口径的效果观察。
4. 汇总成周末复盘，留下可在后续报告中继续跟踪的研究问题。

四项输出可以分阶段交付，但全部具备并通过验收后，才能称为第一版完整闭环。

### 2.2 非目标

- 不读取账户、资金、真实持仓、订单或交易登录状态，不执行任何订单操作。
- 不提供收益保证，不把候选回放描述为真实交易业绩。
- 不通过 AI 自动调整策略参数或修改已发布判断。
- 不在第一版开展多策略路由、全市场覆盖或自动因子挖掘。
- 不以桌面应用、复杂 Web 前端或托管服务作为第一版的必要条件。

## 3 用户与使用场景

主要用户是愿意自行配置数据工具、能够理解研究与真实交易区别的个人港股投资者。第一版优先提供本地运行、命令入口和可读 HTML / Markdown 报告。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 首次使用 | 运行合成演示 | 看懂输入、候选、跟踪和报告之间的关系，无需提供凭证 |
| 盘后研究 | 选择研究日并取得输入，运行主线 | 得到当天机会与行动计划，知道数据缺口和需要复核的内容 |
| 次日跟踪 | 提供新输入并绑定前序结果 | 延续已有候选，保留旧判断，解释新增、失效和状态变化 |
| 效果观察 | 读取已验收研究事件和行情 | 得到可复算的结果，不将缺失成本或未结束候选计成已实现收益 |
| 周末复盘 | 汇总指定期间的研究产物 | 得到本周总结、下周关注项及有依据的研究建议 |
| 后续验证 | 继续读取已记录研究问题 | 更新问题进展，保留原始建议和证据，不直接改写策略 |

## 4 产品流程

```mermaid
flowchart LR
    A[指定研究日与研究池] --> B[获取数据与证据]
    B --> C[输入校验]
    C --> D[机会扫描与候选跟踪]
    D --> E[每日行动计划]
    E --> F[效果观察]
    F --> G[市场环境与周末复盘]
    G --> H[下周关注与待验证问题]
    H -.人工确认研究安排.-> A
```

主线依赖交易日、研究池、行情和前序状态。公司背景、环境观察和周报属于独立的补充环节，失败时说明降级原因，不反向修改或阻断已成立的主线结果。

首次运行可以不提供前序状态，但必须明确标为起始研究。后续运行显式绑定前序结果，不能悄悄当作新起点抹掉已有候选。

## 5 功能需求

### 5.1 数据与证据

| 编号 | 要求 |
| --- | --- |
| DATA-01 | 明确研究日、最新完成交易日、研究池版本和基准，不以机器当前时间推断业务日期 |
| DATA-02 | 分开保存数据来源与访问工具，保留来源时间、获取时间、复权、币种、单位及原始证据引用 |
| DATA-03 | 对日期、覆盖、历史长度、重复记录、OHLC 关系和内容绑定进行校验，输出可定位的失败原因 |
| DATA-04 | 对真实交易日历保存来源证据，不将演示工作日表作为真实日历 |
| DATA-05 | 背景事实与行情输入隔离；公告、财务和研报按发布时间记录，不默认影响 HK-M1 数值规则 |
| DATA-06 | 缺字段、错标的、来源冲突和无权限时报告缺口，不补零、不静默切换来源 |

当前输入合同固定 140 个池成员、至少 126 个有效覆盖、每个至少 120 根有效日线。这是现有引擎的兼容约束，不是产品必须覆盖 140 只股票的业务目标。第一阶段沿用；是否配置化在后续设计中明确，不在本 PRD 中直接放宽。

### 5.2 机会发现

| 编号 | 要求 |
| --- | --- |
| SCAN-01 | 第一版仅使用 HK-M1，沿用已公开规则和参数，保持独立公开策略版本 |
| SCAN-02 | 输出合格候选、排序依据和可解释的过滤结果 |
| SCAN-03 | 为候选记录信号日期、规则版本、依据、模拟进入与退出条件 |
| SCAN-04 | 无合格机会属于正常结果，报告不得暗示必须每天产生推荐 |
| SCAN-05 | 背景资料与模型解释不得变成未经声明的策略条件 |

具体计算与事件约定以 [HK-M1 策略说明](strategy.md)为基线。本次产品规划不修改其经济含义。

### 5.3 候选跟踪与每日行动计划

| 编号 | 要求 |
| --- | --- |
| DAILY-01 | 接续前序候选与事件，区分新增候选、已有候选和已终止候选 |
| DAILY-02 | 根据已记录条件推进模拟状态，保留状态变化日期和原因，不回写原始信号 |
| DAILY-03 | 输出当天关注清单，包括对象、研究动作、触发或失效条件、依据及数据状态 |
| DAILY-04 | 将规则产生的状态、AI 的背景解释与需要人工处理的问题分开呈现 |
| DAILY-05 | 已终止候选保留历史，已有开放候选不重复创建，容量遵守现有生命周期合同 |
| DAILY-06 | 区分事后日线回放和当时取得的前向证据，不将回放中的模拟事件描述为当时已知的事实 |

每日行动计划至少包括：

| 内容 | 说明 |
| --- | --- |
| 日期与版本 | 研究日、数据截至日、研究池与规则版本、前序引用 |
| 当日机会 | 新候选与入选依据；无候选时明确说明 |
| 已有候选 | 原状态、新状态、变化原因及剩余关注条件 |
| 研究动作 | 继续观察、等待条件、模拟状态变化、需要人工复核等明确类别 |
| 风险与缺口 | 失效条件、缺失证据、来源冲突或降级项目 |
| 背景资料 | 可选公告与公司背景，附来源和时间，与信号依据分开 |

这里的行动计划是研究与人工判断的辅助，不是下单指令，也不依赖真实账户信息。

### 5.4 策略效果观察

| 编号 | 要求 |
| --- | --- |
| EVAL-01 | 仅消费已确认的研究输入与事件，保留评价对象、区间、策略版本和输入引用 |
| EVAL-02 | 区分信号级、候选级和组合级结果，不能将候选平均收益直接命名为组合净值 |
| EVAL-03 | 已结束与未结束候选分开统计，明确模拟进入、退出及日线处理假设 |
| EVAL-04 | 成本、滑点、资金配置和基准口径需要显式定义；未定义时不输出净收益或完整组合结论 |
| EVAL-05 | 同时保留成功、失败、跳过与失效结果，不只展示成功案例 |
| EVAL-06 | 评价器只产生观察结果，没有改写策略、信号或候选状态的权限 |

第一步评价候选与事件的后续表现，并提供同区间的基准比较。组合级评价必须另行确认资金配置、成本和风险口径后才能实现。绩效指标是研究观察，不是盈利验收指标。

真实前向观察、历史回放和合成演示必须分别标识，不能混为一条业绩序列。研究池成员选择及幸存者偏差需要在结果中说明。

### 5.5 市场环境观察

| 编号 | 要求 |
| --- | --- |
| CONTEXT-01 | 按研究日记录可用的市场环境事实，保留来源、时点和覆盖范围 |
| CONTEXT-02 | 区分事实与解释，不由单个案例推断策略长期有效性或因果关系 |
| CONTEXT-03 | 作为只读旁路，不调整候选优先级、准入条件或生命周期 |
| CONTEXT-04 | 数据不足时标记缺口；环境模块失败不阻断已确认的每日主线 |

第一版具体环境指标需结合可用数据确定，不默认具备完整南向、全市场或公司行动覆盖。

### 5.6 周末复盘与后续验证

| 编号 | 要求 |
| --- | --- |
| WEEKLY-01 | 使用显式起止日期及期间已确认产物，披露缺失研究日，不默认“最近五份报告”等于完整交易周 |
| WEEKLY-02 | 汇总机会、状态变化、效果观察、市场环境和数据问题 |
| WEEKLY-03 | 分开记录事实、解释、建议和待验证问题；建议必须有依据 |
| WEEKLY-04 | 待验证问题保留首次提出日期、证据、后续观察条件与当前进展 |
| WEEKLY-05 | 下一轮可以继续关注问题，但建议不能自动成为策略上游或参数变更 |
| WEEKLY-06 | 无候选、未结束候选或证据不足的周也应生成有效复盘，不强行得出好坏结论 |

周报至少包括本周概览、候选变化、已发生结果、环境与限制、下周关注清单。规则修改建议单独列出，由使用者确认，不自动应用。

## 6 数据来源与接入

| 来源 / 工具 | 主要职责 | 边界 |
| --- | --- | --- |
| 恒生聚源数据地图 MCP | 公告、财务、研报、行业与结构化事实，补充公司背景与核验依据 | 实际覆盖以权限与接口为准；不默认变成 HK-M1 信号输入 |
| 腾讯自选股 WeStock MCP | 历史日线、前复权价格、成交额与成交量，以及行情抽样核对 | 复权重述、币种与单位必须核对，历史变化不能静默拼接 |
| Futu Skills / OpenD | 证券信息、行情快照、K 线、明确开盘价与辅助交易字段 | 仅使用只读研究能力；现价不能替代开盘价，经纪商字段不能当作完整南向净买入 |

第一阶段保留现有文件桥接，先证明数据合同与研究流程能够衔接。原生连接器不作为这一阶段的必要交付。

真实接入验收需要在合法配置的本地环境中确认实际字段、来源时间、原始响应和转换结果。服务配置存在、合成测试通过或本机安装完成，均不能代替真实接入结论。

不同来源独立记录，不要求每轮都调用三家。背景数据不可用时允许降级；主线必需行情不可用时停止该次研究。

## 7 状态与交付设计

### 7.1 状态对象

| 对象 | 必须保留的内容 |
| --- | --- |
| 研究输入 | 研究日、研究池、数据来源、口径、文件绑定与质量结果 |
| 候选 | 标的、原始信号日期、规则版本、固定条件及完整事件记录 |
| 单次运行 | 前序引用、运行状态、输入输出绑定、失败或降级原因 |
| 效果观察 | 评价区间、评价层级、计算假设、输入引用与限制 |
| 研究问题 | 提出日期、问题内容、依据、观察条件、进展与结论 |

首次运行初始化状态。续接要求日期递增、前序产物一致和已有历史不被重写。终止候选及已结束研究问题仍保留，不通过删除来改善结果。

### 7.2 人类可读交付

| 交付 | 必须回答的问题 |
| --- | --- |
| 每日行动计划 | 今天关注什么，之前的候选怎样变化，依据和风险条件是什么 |
| 效果观察报告 | 哪些事件已有结果，采用什么口径，哪些结论还不能下 |
| 周末复盘 | 本周发现了什么，哪些判断得到支持或失效，下周继续验证什么 |

每份报告必须标明合成演示、历史回放或真实前向观察的类别。AI 生成的解释需要引用相应事实，不得修改程序输出的数字和状态。

机器产物与可读报告要绑定同一次运行。新增字段与文件结构在模块设计时形成正式合同，不在此处宣称已有实现。

### 7.3 失败处理

| 情况 | 处理 |
| --- | --- |
| 必需输入缺失、日期错误、内容绑定不一致、旧状态损坏 | 停止主线，输出具体原因，不发布成功结果 |
| 复权重述或已记录历史变化 | 停止续接，进入独立复核，不静默修复 |
| 公告背景、环境或周报不可用 | 记录降级，保留有效主线，不重复拉起主线 |
| 写盘中断 | 保留失败证据，部分输出不作为有效前序状态；后续使用新目录 |
| 解释文字与计算事实冲突 | 报告不通过验收，不修改计算结果迎合解释 |
| 需要改变规则或安全范围 | 等待所有者明确授权，不由执行者自证授权 |

仅瞬时问题可以在明确预算内重试。日期、哈希、版本、账本与安全边界错误不得自动重试或自修复。

## 8 脱敏与公开边界

| 内容 | 处理方式 |
| --- | --- |
| 产品目标与研究流程 | 保留，按完整研究闭环组织 |
| 已公开策略方法与参数 | 保留，不继承私人版本的验收与结论 |
| 数据工具名称与分工 | 保留，不携带凭证或私人连接配置 |
| 私人研究池、真实数据与生产状态 | 不公开，由使用者本地提供 |
| 私人报告、收益、任务与审计记录 | 不迁入公开仓库，不通过替换名称冒充示例 |
| 示例与测试数据 | 独立生成合成数据；可再分发数据需有明确授权 |
| 仓库历史与个人路径 | 独立公开历史，使用可移植配置与相对项目路径 |

第三方数据与工具遵循各自条款。代码许可不代替数据许可，也不将供应商名称描述为合作背书。

## 9 当前实现与差距

本节记录需求确认时的实现基线，不代表后续模块已验收；当前交付范围见 [版本说明](release.md)。

| 模块 | 已有基础 | 需要补齐 |
| --- | --- | --- |
| 数据 | 标准包、来源声明、质量校验与合成生成器 | 日常获取任务、实际字段映射及可复核接入说明 |
| 机会发现 | HK-M1 扫描与规则说明 | 与产品层每日计划衔接，保留筛选理由 |
| 候选跟踪 | 模拟生命周期、前序产物与历史绑定 | 产品化的状态说明、长期连续演示及异常恢复流程 |
| 每日计划 | 扫描与跟踪报告 | 明确的关注清单、研究动作、风险与人工复核项 |
| 效果观察 | 候选事件记录 | 独立评价器、基准与成本口径、评价报告 |
| 市场环境 | 目标与数据来源分工 | 独立只读模块、具体指标及降级行为 |
| 周末复盘 | 产品目标 | 期间汇总、建议与待验证问题记录、后续跟踪 |
| 运行组织 | 本地命令与新目录输出 | 统一编排、终态与降级交付，之后再考虑调度 |

原项目中的对应能力应逐项审查后迁出，不能直接复制生产任务、私人绑定、历史结论或临时 prompt。需要重做的部分按公开版合同实现。

## 10 实施阶段与验收

| 阶段 | 交付范围 | 验收标准 |
| --- | --- | --- |
| P0 产品与接口确认 | 确认本 PRD、模块边界和现有规则基线 | 四项产品输出、非目标及公开范围无歧义；需要所有者决定的口径已列出 |
| P1 日常研究主线 | 输入、扫描、候选续接、每日行动计划 | 演示新增、无机会、等待、模拟进入、退出与缺口；每次变化可追溯，不能覆盖旧状态 |
| P2 效果观察 | 候选评价、基准比较与评价报告；确认后补组合口径 | 结果可按事件复算，已结束与未结束分开；缺成本不输出净收益，回放不伪装前向 |
| P3 环境与周末复盘 | 独立环境、期间复盘、待验证问题延续 | 缺失日期显式说明；复盘引用事实，问题可续接，建议不自动改规则；旁路失败不破坏每日结果 |
| P4 完整公开交付 | 使用文档、连续场景演示与发布边界 | 从首次研究到周末复盘再到下一轮问题跟踪完整可演示，敏感实例不进入公开文件 |

调度、原生连接器和多策略不作为 P1 的前置依赖。实施时每阶段先确认任务范围，再修改实现，不借文档授权扩大运行或账户权限。

### 10.1 关键验收场景

| 场景 | 预期行为 |
| --- | --- |
| 无候选日 | 生成有效每日计划，不强行推荐 |
| 连续多日同一候选 | 不重复创建，保留原信号并追加变化 |
| 次日所需开盘证据缺失 | 不以现价代替，不伪造模拟事件 |
| 前序产物或历史被修改 | 拒绝续接并定位问题，不自修复 |
| 背景或环境数据失败 | 明确降级，有效每日主线继续交付 |
| 只有未结束候选 | 不报告已实现收益或已验证 Alpha |
| 复盘期间缺少研究日 | 披露缺口，不假装完整覆盖 |
| 复盘提出规则改动 | 保留建议，不直接执行 |
| 本地配置含凭证 | 仅本地保存，公开文件不得包含 |
| 相同输入与规则重新运行 | 确定性计算结果一致，解释文字与事实一致；不要求模型自然语言逐字节相同 |

验收记录必须区分合成单元场景、故障注入、真实只读接入和真实调度。前一种结论不能代替后一种；研究表现好坏不作为工程通过条件。

## 11 需要在模块设计前确认的事项

以下事项不阻碍 PRD 讨论，但在对应阶段实现前需要明确决定。

| 事项 | 当前基线或建议 | 确认时点 |
| --- | --- | --- |
| 使用界面 | 第一版优先本地命令及 HTML / Markdown，不新增复杂前端 | P0 |
| 研究池规模 | P1 沿用现有合同；是否支持其他规模单独评估 | P0 |
| 每日计划格式 | 使用研究动作和状态变化，不映射真实账户操作 | P1 |
| 组合、成本与基准口径 | 不默认等权、零成本或已有资金配置；采用什么方案由所有者确认 | P2 |
| 市场环境指标 | 根据实际权限和研究用途确定，不预设全市场覆盖 | P3 |
| 复盘期间 | 指定起止日期并核对交易日，不默认完整自然周 | P3 |
| 部署与调度 | 先人工触发闭环；定时运行需单独任务与授权 | P4 之后 |
